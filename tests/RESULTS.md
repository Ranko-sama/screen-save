# Screen Save 本机验收记录

日期：2026-10-06。设备：Xiaomi Book Pro 14，Windows 11（10.0.28000）x64，Intel Arc B390，驱动 32.0.101.8359，内屏 120 Hz。系统亮度接口提供 0–100。

## 当前结论

功能与浏览器工作负载测试通过，正式 EXE 连续全黑运行 15 分钟通过；**整体性能验收不能判为全部通过**。DWM 的 GPU 引擎利用率合计从正常约 20.64% 升至全黑约 30.13%（增加 9.49 个百分点，相对增加 45.98%），DWM 私有工作集也增加约 25.76 MiB。若 ±5% 要求包含 DWM/GPU，这个颜色矩阵方案未达标。按约束保留实测结论，不添加遮罩或其他补偿机制。

## 交付程序

- `dist/ScreenSave.exe`：104,448 bytes（102 KiB），C++/Win32 x64，单进程，静态链接运行库。
- SHA-256：`676D7D182C950A58714AA0912D7B059D2B203519EAC578D7AACA053E5EE919E5`。
- 三个备用快捷键：Ctrl+Alt+PageDown、Ctrl+Alt+PageUp、Ctrl+Alt+B。原生 Fn 亮度键未接入，未宣称本机已验证可拦截。
- 无遮罩；只有不显示的消息接收窗口。阻塞消息循环，没有周期任务。颜色矩阵与保活状态只在用户操作时改变。
- 源码无网络调用。导入表只有 USER32、SHELL32、MAGNIFICATION、ole32、OLEAUT32、KERNEL32；WMI 连接本机 ROOT/WMI。
- 测试工具及本地 HTTP 服务不属于交付程序。
- 全黑运行期间检查进程端点：TCP 连接 0，UDP 端口 0。

## 颜色与操作

原型将 RGB 系数依次设为 0.5 和 0，各保持 25 秒，再恢复原矩阵。Initialize、Read、Set、Restore 均返回 1，进程退出码为 0。用户目视确认：“先变暗，再全黑，最后恢复正常”。

浏览器专用工具访问 `http://127.0.0.1:18741/`：正常、半暗、全黑时均可读取正常颜色截图。半暗与全黑的同一静态色块截图均为 2,502 bytes，逐字节一致；全黑时输入“黑屏输入验证”并点击按钮成功。

Windows computer-use 使用独立的 Win32 原生测试窗口（`tests/native-fixture.cpp`）：全黑时截图仍显示正常色块；输入 `BLACK SCREEN INPUT OK`、点击确认均成功，窗口显示该文字与 `Input confirmed`。六个色块中心的 RGB 值在正常／全黑截图中逐一一致。截图有压缩及鼠标提示光晕，因此未把整张截图描述为像素完全一致。

上述原生测试验证了 Windows.Graphics.Capture 窗口截图和桌面键鼠输入路径。Chrome 窗口的原生截图因工具无法可靠确定浏览器网址而受限，没有绕过限制；Chrome 使用浏览器专用截图工具验证。未据此宣称所有截图软件或所有 agents 均已覆盖。

## 正式程序功能检查

通过 Windows computer-use 向独立原生测试窗口发送实际快捷键，外部测试工具读取 WMI 与颜色矩阵：

| 操作 | 实测结果 |
| --- | --- |
| 正常范围降低一次 | 系统亮度 95 → 90，颜色系数保持 1 |
| 系统亮度设为 0 后再降低一次 | 系统亮度仍为 0，颜色系数变为 0.95 |
| 0.95 状态按 Ctrl+Alt+B | 系数变为 0 |
| 再按 Ctrl+Alt+B | 恢复 0.95 |
| 从 0.95 调亮一次 | 系数恢复 1，系统亮度仍为 0 |
| 再调亮一次 | 系统亮度升为 5 |
| 从系统亮度 0 连续降低 21 次 | 到达第 20 档后保持系数 0，硬件亮度仍为 0 |
| 接着连续调亮 20 次 | 系数恢复 1，硬件亮度仍为 0 |
| 压暗／全黑 | 系统执行状态标志为 3（SYSTEM_REQUIRED + DISPLAY_REQUIRED） |
| 恢复正常颜色 | 上述执行状态标志回到 0 |

测试后将系统亮度恢复测试前的 100。测试发现并修复了本机 WMI 方法成功但不返回对象时的空对象释放问题，修复后重新完成了上述检查。

正式 EXE 的第 20 档下，原生窗口再次完成输入 `RELEASE BLACK INPUT OK` 和按钮确认，截图保持正常颜色：[截图](artifacts/release-black-input.png)。托盘退出的手动验证结果待补充。

| --- | ---: | ---: | ---: |
| FPS | 120.0001 | 120.0001 | 约 0% |
| 帧间隔 P95 | 8.5 ms | 8.5 ms | 0% |

| 固定计算耗时中位数 | 4.8 ms | 4.7 ms | −2.08% |

六轮 hidden_events 与 blur_events 均为 0，结束时 visibility=visible、has_focus=true。该结果只支持所测工作负载，不代表所有 benchmark 的性能保证。

## 持续运行与资源

正式 EXE 连续保持全黑，完成 900 秒前台渲染测试：119.9988 FPS，帧间隔 P95 为 8.5 ms，最长帧间隔为 16.7 ms，hidden_events=0、blur_events=0，结束时仍 visible 且 has_focus=true。

独立电源监测持续 930.016 秒：显示器状态始终为 1（On），non_on_events=0，suspend_events=0。结束时距最后一次系统输入 578.672 秒。监测程序自身不申请保活。读取的电源计划为接通电源时“从不息屏”、电池时 180 秒，因此没有宣称此轮实际触发并覆盖了接通电源的自动息屏倒计时；保活请求的设置和释放则独立读回验证了 3 → 0。未修改电源计划。

正式 EXE 的 923.196 秒资源采样：CPU 时间增量为 0，平均 CPU 为 0.000%；结束时私有内存 2,363,392 bytes（2.25 MiB），工作集 16,207,872 bytes（15.46 MiB）。这里的 0 来自系统进程 CPU 计时器的观测精度，不声称绝对零开销。CPU 百分比按单个逻辑处理器为 100% 计算；本机共 16 个逻辑处理器。

持续测试结束后读回颜色系数仍为 0、执行状态标志为 3；按快捷键恢复后系数为 1、执行状态为 0，硬件亮度保持测试前的 100。

原始记录：[900 秒渲染结果](artifacts/benchmark-soak.json)、[电源事件](artifacts/soak-power-events.txt)、[进程采样](artifacts/soak-end.json)。

### DWM 额外开销

正式 EXE 保持运行，测试页保持前台并持续同一 Canvas/计算负载。全黑、恢复正常各采样三轮；每轮通过 Windows 性能计数器采集 30 个一秒样本，再取三轮平均值的中位数。两组顺序为全黑后正常，其他用户进程继续运行。

| 指标 | 正常 | 全黑 | 相对变化 |
| --- | ---: | ---: | ---: |
| DWM CPU（单核为 100%） | 14.66% | 12.72% | −13.27% |
| DWM 私有工作集 | 430.32 MiB | 456.08 MiB | +5.99% |
| DWM GPU 引擎利用率合计 | 20.64% | 30.13% | +45.98% |

GPU 指标为该进程所有 GPU 引擎计数器之和，不等同于任务管理器的整机 GPU 总百分比。DWM 服务整个桌面，数据包含其他窗口与系统背景活动，不能把所有差值都严格归因于此程序；但三轮全黑 GPU 值为 30.10%、30.13%、30.14%，三轮正常值为 20.64%、20.64%、20.65%，因此不能宣称颜色矩阵没有合成开销。CPU 的下降也不作性能改进结论。

正式 EXE 自身在这六轮中均测得 CPU 时间增量为 0。初步的单轮资源数据仅作过程记录；正式比较采用以下三轮文件。原始数据：[正常三轮](artifacts/resources-normal-three.json)、[全黑三轮](artifacts/resources-black-three.json)、[比较结果](artifacts/resources-comparison.json)。

## 测试工具

- `color-probe.cpp`：限时应用颜色矩阵并恢复；参数仅用于开发测试。
- `native-fixture.cpp`：普通 Win32 窗口，提供色块、编辑框和按钮。
- `bench.html`、`serve.cjs`：单一本地测试页，服务仅监听 127.0.0.1。
- `ReadState.cs`：只读颜色矩阵和系统执行状态。
- `soak-monitor.cpp`：记录显示电源与休眠消息；不申请保活。
- `wmi-probe.cpp`：诊断本机 WMI 方法参数和调用结果。

它们全部保留在源码目录，不随 EXE 发布。
