# 会话恢复修复与低频回归

2026-10-08。以 [baseline.cpp](artifacts/recovery-fix/baseline.cpp) 为固定修复前版本。本轮没有真实注销、关机、自动反复暗屏或压力测试。

## 已确认并修复

1. 正常结束 Windows 会话时，原窗口过程没有 `WM_ENDSESSION` 分支，恢复只在消息循环之后执行。Windows 不保证在结束会话通知返回后继续运行这段代码。现增加一个分支，在 `wParam != 0 && isDark` 时同步调用原来的 `ToggleBlack()`；取消结束会话或本来处于正常状态时不改显示。[Windows 契约](https://learn.microsoft.com/en-us/windows/win32/shutdown/wm-endsession)
2. IME 诊断构建脚本从当前源码读取基线，但当前源码已经关闭 IME，候选再添加一次，形成一次／两次调用。脚本改读已保存的历史基线，并把生成文件及未来运行输出放入独立的 `build/memory-map/reproduce-startup/`，避免覆盖历史记录。回归生成零次／一次调用，去除输出路径差异后，源码仅差此调用；两份程序均构建成功，没有启动诊断程序。[结果](artifacts/recovery-fix/ime-generator-result.json)
3. 内存报告中的“节省 24 KiB”改为“本次单次观察中低 24 KiB”；保留原始数字，明确调用前已存在初始差异，不据此证明稳定收益。也明确历史少数字段读回不等于完整颜色表恢复验证。

## 真实源码的内存回归

[recovery-model-probe.cpp](recovery-model-probe.cpp) 直接包含各版本的正式源码，替换其显示、WMI、光标、保活和退出调用为内存记录器。没有另写一套产品状态机。测试不创建窗口、不启动产品入口、不操作实体显示；检查的两个模型 EXE 均不导入真实显示／鼠标移动／保活写入接口，见 [隔离检查](artifacts/recovery-fix/model-isolation.json)。

覆盖：

- Matrix/Gamma、正常/暗态，关机与注销通知；确认会话结束前恢复，取消通知与查询通知不改变状态。
- 完整的 25 项矩阵、768 项 Gamma、硬件亮度、光标逻辑状态和保活标志。只要求恢复被当前模式改变的状态，不要求无关 API 也写一遍。
- 取消会话后继续双向模式交接、正常切换与恢复；逐次记录显示写入，检测交接中两种颜色效果同时撤掉的间隙。
- 下一次进入前改变外部矩阵、Gamma 和硬件亮度（73→41），确认采集新的快照。
- `WM_CLOSE` 仍增加一次退出请求；这不等于模拟了真实主循环退出后的全部资源清理。
- 在读取坐标之后注入一次模型中的并发移动，验证旧坐标回写是否覆盖新位置。

模型按成功的系统 API 契约运行，不证明关机时驱动一定执行成功，也不证明光标的真实硬件刷新。构建及运行入口为 [build-recovery-regression.ps1](build-recovery-regression.ps1)，使用本轮固定源码快照。负对照必须正常返回退出码 1、提供完整检查汇总，并命中指定失败项；崩溃不计为消融成功。

## 光标修复的实体鉴别

源码与模型显示条件性风险：若读到位置 A 后，外部移动到 B，再写回 A，新位置会被覆盖。模型人为安排了这个交错，尚未据此证明本机真实操作出现过该交错或误点击。再次读坐标不能消除最后一次读写之间的窗口。直接删除刷新则会重新引入本机已经确认的“静止光标不立即出现”。

第一个候选使用相对零移动的 `SendInput(MOVE | MOVE_NOCOALESCE)`，没有绝对坐标回写。用户只做一次慢速黑屏／恢复，反馈仍需手动移动鼠标才出现，故候选舍弃，没有进入正式代码。操作前后只读快照的全部矩阵和 Gamma 字节相同，执行请求均为 0；这些数据没有推翻用户的光标失败反馈。[结果](artifacts/recovery-fix/manual-result.json)

第二个候选仅在光标显示后调用一次 `DwmFlush()`，同样没有坐标写回或鼠标注入。用户在重新启动的候选上完成一次慢速黑屏／恢复，反馈“仍需移动鼠标”，故此候选也舍弃。操作前后属于同一进程，完整矩阵和 Gamma 表均恢复，系统执行状态读数均为 0；光标即时恢复仍未通过。[本轮结果](artifacts/recovery-fix/dwm-retest-result.json)。本轮没有再追加其他候选或切屏测试。

**当前正式版本保留原来的坐标刷新。代码及模型证明特定交错时序下存在风险，但没有据此证明本机真实 agent 操作发生过旧坐标覆盖。** 后续两轮真实操作结果及工具串行化限制见 [REAL-CURSOR-RESULTS.md](REAL-CURSOR-RESULTS.md)。没有加入轮询、锁鼠标、额外窗口、重试、失败兜底或恢复框架。

## 交付与边界

正式源码目前与 `session_only.cpp` 快照逐字节相同，正式 EXE 已重新构建，仍为 25,600 字节（25 KiB）；见 [构建信息](artifacts/recovery-fix/release.json)。其入口和消息循环没有新增后台工作。

失败候选已通过 `WM_CLOSE` 正常退出（退出码 0），已重新启动 `dist/ScreenSave.exe`；启动前验证源码和 EXE 均匹配上述构建记录。重新启动后的完整矩阵和 Gamma 表与测试前一致，见 [恢复正式版记录](artifacts/recovery-fix/release-restart-result.json)。退出后及重启时的系统执行状态读数为 2；该读数属于系统范围，不能据此归因于本程序，也不能声称此时全系统没有显示保活请求。候选测试前后的读数均为 0。

本轮没有重测 CPU、GPU、DWM 或稳态 RAM，不能声称性能进一步下降。测试代码、日志、候选均不随正式 EXE 发布。未创建 Git 提交。
