# 实际 Computer Use / Browser Use 复现尝试

2026-10-08。结论：**未复现先前推测的并发旧坐标覆盖或误点击；工具没有产生所需的原生输入重叠。另记录到两次恢复时各轴增加 1 像素，原因尚未确认。**

## 实际执行

- 使用未修改的 `dist/ScreenSave.exe`，PID 29556。源码及 EXE 哈希与 [正式构建记录](artifacts/recovery-fix/release.json) 一致。
- Browser Use 使用 ChatGPT 内置浏览器，访问仅监听 `127.0.0.1` 的本地测试页；黑屏期间点击 B、A 各一次，恢复后点击 B 一次。页面记录目标正确、三个点击均为可信浏览器输入事件。
- Computer Use 通过 `@oai/sky` 操作独立 Win32 测试窗口，真实点击 A、B 各一次，完成从左到右的拖动两次。窗口计数为 A=1、B=1、拖动=2。
- 仅两轮黑屏／恢复，四次真实 `Ctrl+Alt+B`。两次暗态矩阵系数均为 0；恢复后完整 25 项矩阵、768 项 Gamma 表均与本轮开始时一致。系统执行状态依次为 2、3、2、3、2；这是全系统读数，不能据此归因基线中的其他显示请求。
- 临时观察器只记录真实鼠标／键盘事件，不注入输入，不修改正式进程。原生目标只记录收到的事件和自身计数，不控制黑屏、不注入输入。没有调试暂停、产品补丁、修改产品调用间隔或压力循环。

## 实际观察到的坐标变化

两轮拖动均从 `(221,499)` 到 `(811,499)`。恢复快捷键到达附近，DPI-aware 原生目标随后读到 `(812,500)`。没有回到拖动起点，后续 B 点击落在正确目标。

这是同一原生目标、同一坐标读取方式得到的 **(+1,+1)** 变化，单独保留，不当成原先推测的并发旧位置覆盖。尚未定位它来自程序、坐标换算还是输入工具；本轮不继续增加切屏次数或修改正式代码。

原生目标调用了 `SetProcessDPIAware()`，观察器没有调用；两者没有记录实际生效的 DPI 上下文。观察器键盘回调读到的坐标与原生目标不同，不能据此直接确定差异来自 DPI 换算，也不能将两份日志的坐标简单相减。上述 1 像素变化仅使用原生目标自己的记录。

## 三位干净上下文子代理的独立复核

后续分别从代码契约、原始测试证据和修复优先级审查，结论一致：坐标读写具有条件性风险；模型验证所假定交错的后果，未验证本机触发；两轮原生输入没有提供该交错的证据。Browser Use 的 `trusted` 点击仅证明浏览器分派了正确目标事件，不能证明经过 Windows 全局鼠标路径。页面时钟与系统 tick 也未对齐，仅凭页面 JSON 无法独立确定暗态时段；暗态操作顺序来自工具执行记录及显示快照。

将其列为静态审查风险合理，将其当作已发生、必须立即修复的 agent 故障证据不足。保留当前已验证的静止光标恢复实现，不为强制交错模型的红项替换成实体失败的候选；仅在出现实际症状或有依据的新方案时继续调查。三位子代理均只读，没有运行测试或操作屏幕。
